## 逐图检查

1. **先看图，再读词条。** 用一句短语写下实际看到的主体、动作或界面文字，再与当前 `word`、`meaning`、必要的 Context 或 Example 核对。细节看不清时如实记录。
2. **判断是否表达当前义项。** 通用词可以用来自任何领域的照片、插画或示意图。动作图要看得出动作，抽象词要有能帮助回想词义的具体线索。游戏专名要保留能辨认该角色、道具或地点的特征。
3. **按卡片尺寸复看。** 在不超过 200 px 宽的显示下检查焦点、文字和背景。需要裁切时，记录应保留的部位，并复看裁切预览。依赖微小字幕或整页菜单才能辨认的图片，单独记录可读性问题。
4. **对照易混图。** 把表达相近义项的图片放在一起看。标出重复画面、近似构图和可能让人记错义项的图。对截图、专名和剧情线索记录证据限制或剧透范围。
5. **另记来源与发布条件。** 记录图片来源和已有的再分发结论。第三方照片、图标和插画均可成为候选。随仓库或共享牌组分发所需的依据，参见[图片工作流](../README.md#images)。视觉匹配结论在许可未知时仍可记录。

## 审查顺序

- **通用实体与动作。** 先看器物、食材、地形和有明显动作的图。概念清楚时，通用照片或示意图也可以作为替换方向。
- **游戏专名与界面。** 对照角色、地点、道具和界面状态。优先找出相似道具、不同游戏作品或不同菜单之间可能误认的画面。
- **抽象词与剧情。** 检查画面能否表达词义或具体记忆线索。看起来好看但无法引出义项时，建议换图或留空。

每组可分批审查。批次规模按画面的相似度和辨析难度决定。全部 536 张均需有独立结论，适合留空的词条计入已审查。

## 审查记录与决定

每张图记录稳定 ID、词语和当前释义、实际画面、200 px 下的可读性、匹配理由或混淆点、建议、来源以及适用的再分发依据。需要换图时写清目标画面，待核实的游戏身份、来源或许可写出具体缺项。

| 建议     | 判定标准                                         |
|:---------|:-------------------------------------------------|
| 保留候选 | 画面清晰，能支持当前义项，可继续核对发布条件     |
| 调整构图 | 素材与词义匹配，裁切或更清晰的原帧可突出关键线索 |
| 寻找替代 | 当前画面易误导，或存在更容易辨认的画面           |
| 保持无图 | 图片提供的记忆线索有限，或目前缺少可靠的视觉依据 |

例如，`arrow-weapon` 的抽查图能分辨箭头、箭杆和尾羽，可作为保留候选的参考。`album-ui` 的画面含照片缩略图和 `Album` 标签，应检查缩图后这些线索能否独立说明数字相册。示例用于统一审查标准，具体接回名单以逐项记录和你的确认结果为准。
